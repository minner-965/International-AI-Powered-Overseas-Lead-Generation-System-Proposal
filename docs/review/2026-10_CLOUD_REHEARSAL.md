# 云端全新安装演练（2026-10-22）

目的：在把系统装到 Simon 的 Windows 电脑之前，先在隔离环境里从空数据库跑通一遍，把新装才会遇到的问题提前修掉。开发者文档。

## 环境
- 云端容器，PostgreSQL 16（生产镜像是 17），无 Docker：用与容器 init 相同的方式按文件名顺序执行 `database/migrations/*.sql`，应用直接 `node src/server.js` 启动。
- 外部服务全部本地化：Exa/Tavily/Hunter 指向本机关闭端口，发信 `OUTBOUND_EMAIL_PROVIDER=NONE`，飞书指向本地模拟服务。**零真实外部调用**。
- 示例数据带 "(rehearsal)" 标记，只在演练库里。

## 发现并已修复
1. **新装库执行 `phase7:migrate` 失败**：容器 init 已建好全部表，但迁移账本为空，执行器重跑 025 时被 PostgreSQL 拒绝（视图列改名）。新增 `--baseline`：只在账本为空且库里已有最新表时登记账本，不重跑 SQL，每个迁移自己的校验仍然执行；已有账本时拒绝。安装脚本自动选择 baseline 或正常 apply。
2. **同一个人连续改两次阶段，第二次被记成"系统"且备注丢失**：原触发器靠比较字段猜测是不是人改的。改为应用在事务里写入 `leadgen.stage_actor`，触发器据此记录；没有操作人才算邮件事件。064 尚未在任何真实库执行，原地修正。
3. **CRM 同步记录不会自动发出**：只有显式入队的记录才同步，首封邮件产生的记录从不入队，临时失败的记录在队列重试用完后也不再重试。新增 `crm-outbox-dispatch`（配置了 CRM 才运行，每 10 分钟）。跟进扫描同时会把"已批准但因邮件暂停/额度未发"的草稿重新入队。
4. **新装库没有已批准的供应类目，且界面没有批准入口**：新增 `scripts/setup-supply-categories.mjs`（通过现有接口列出候选、建草稿、批准）。界面入口留到正式页面改版。
5. **未导入历史客户时提示"暂时不可用"**：改为"尚未导入历史客户资料"。
6. compose 里新加的飞书/跟进变量会用空值覆盖 `.env.phase7-outreach` 里的设置：已删除，统一从 `.env.phase7-outreach` 读取。

## 没有在云端验证的
- Docker 构建与 `docker compose up`（安装脚本已用 PowerShell 7 测到生成配置文件一步）。
- 真实 SMTP 发信：发信要求 587 STARTTLS + 993 IMAP TLS，没有为演练放宽；发送逻辑由 Postgres 端到端测试（模拟发信）覆盖。
- 真实飞书、Exa、Tavily、Hunter 调用。
- PostgreSQL 17。
