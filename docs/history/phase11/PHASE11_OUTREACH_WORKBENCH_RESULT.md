## 实际链路修正

1. 批准有效期的 ISO 字符串与 PostgreSQL Date 回读统一为相同时间表示，修复摘要误判；没有重写已有批准摘要。
2. 工作进程读取发送记录时补齐原批准的机会、管理决定、联系路径和有效期字段，保证与页面批准一致。
3. 创建发送记录时写入必填执行键与稳定 Message-ID，符合已经迁移的表结构。
4. 仅对从未开始服务调用的 BLOCKED 邮件提供受限重新提交；再次检查当前批准和资格，复用原邮件与执行键。已开始调用、结果歧义及已被接收邮件不走该重试路径。
5. 修复退回草稿再次修改的版本衔接、正式邮件与受控收信统计混淆、平板机会行溢出和深色背景被旧浅色样式覆盖的问题。

## 模型与后续迁移

当前企业筛选、类目匹配和数值评分主要由程序规则执行；写信使用静态模板/提交文本，尚无已经接通的通用大模型推理接口。开发期间 Codex 帮助准备文本不等于系统已经具有大模型运行能力。

公网服务器若要自动进行语言理解、摘要、个性化草拟，需要选定模型服务并实现服务器调用适配器、任务和用量记录、证据约束、错误处理及回归验收；仅填写 API Key 不会自动完成这些接入。
