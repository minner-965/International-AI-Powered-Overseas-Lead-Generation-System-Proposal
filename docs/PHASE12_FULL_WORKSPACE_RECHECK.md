## 已修复

1. 邮件详情打开期间，公司从联系队列移除后，旧窗口仍可能保留操作状态且忙碌状态未解除。现在禁用所有修改、审批和发送操作，保留正文，提示返回选择有效记录，并解除忙碌状态。

3. 清理发现的内部处理说明及口语：自动补证、Provider/Worker 重试、快照、联系路径、旧 SKU 补充流程、由老板沟通等。中英文同步采用资料核验、联系方式、待解决事项、类目评估等业务表述。
4. 资料详情不再展示 HTTP 数字及原始内部状态；已知状态使用中英文页面检查结果，未知状态保留“待确认”。原始网址、标题、时间、公司名称和证据未改写。

项目 dpv-workspace-ui 约束了视觉与业务边界；ui-ux-pro-max 的错误反馈指引用于保留输入、明确失败状态和恢复操作，而非更换已批准的设计方向。

### 保存与审批正向

- 编辑、保存、页面刷新后重新显示已保存正文与主题（浏览器样本）。
- 实际数据库创建草稿、重新连接读取、提交审核、批准版本、再次重新连接核对。
- 修改已批准草稿产生新版本，原审批正文保持不变，新版本未继承旧审批。

### 逆向

- 保存处理中禁用重复操作；旧版本重复保存不产生重复修订。
- 保存失败保留输入；未保存修改阻止审批与发送。
- 放弃修改时取消/确认两条分支；放弃后原保存内容仍在。
- 未提交先审批、错误内容摘要、空主题、失效邮箱、公司退订均阻止对应操作。
- 空主题数据库修订原子回滚；刷新失败和公司移出队列后失效操作关闭。
- 实际SQL并发、IMAP关联、CRM重放、退订顺序继续通过。
